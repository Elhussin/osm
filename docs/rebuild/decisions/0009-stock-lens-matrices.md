# ADR 0009: مصفوفات مخزون العدسات — R08-M01

التاريخ: 2026-11-09. يعتمد R07 وADR 0008. طلب المستخدم إدخال مخزون العدسات وعرضه بمصفوفة تجمع الصنف. هذا الجزء يحقق المصفوفة والإضافة والعكس فقط؛ R08 تبقى in_progress حتى الحجز/الصرف والتحويل والجرد والدفعات/التسلسلات.

## نطاق المصفوفة وتجميع الصنف
المصفوفة للعدسات المخزنية stock_lens: صفوف SPH وأعمدة CYL بخطوة0.25، مع اختيار الفرع ونطاق القوى. المجموعة تضم المنتج نفسه ووحدة البيع وكل المواصفات الأخرى: المادة ومعامل الانكسار والقطر والتصميم واللون والطلاءات. لا جمع تلقائي بين عدسة وزوج أو بين طلاءين أو شركتين أو فرعين. العدسات RX لا تحمل قوى مريض مخزنية وفق ADR 0008، واللاصقة لها BC/AXIS ودفعات/صلاحية وتحتاج مصفوفة مخصصة لاحقًا؛ لم نسطحها في جدول قد يخلطها.

أضيف matrix_family وsphere وcylinder ثابتة إلى Variant، وفهرس product/family ووحدانية product/family/SPH/CYL. تُشتق من JSON المطبعة نفسها في خدمة الكتالوج، مع ترحيل backfill للمتغيرات السابقة؛ لا تغيير SKU أو الباركود أو السعر أو الهوية. لا تعديل للترحيلات القديمة؛ 0002 additive مع data operation، ويدعم اختبار PostgreSQL إعادة اشتقاق الفهرس دون تغيير الأصل. منح runtime الحالية لهوية المتغير تمنع تعديل أعمدة المصفوفة الجديدة.

الشاشة تعرض المتاح والفعلي والمحجوز لكل خلية موجودة، وشرطة «غير معرف» عند غياب المتغير، لا صفرًا مضللًا. إجمالي العائلة للفرع يشمل القوى خارج نافذة العرض. الحدود400 خلية و41 صفًا و17 عمودًا لكل نافذة/طلب؛ يختار المستخدم نطاقًا أصغر عند الحاجة. الجدول داخل تمرير مستقل، مع رؤوس ثابتة واتجاه LTR للأرقام داخل صفحة RTL. لا تتسبب المصفوفة بعرض الصفحة خارج الهاتف.

## الإدخال السريع
حقول الكمية تعني إضافة جديدة، لا استبدال الرصيد. الفراغ والصفر لا ينشئان حركة أو متغيرًا؛ الكمية صحيحة غير سالبة حتى1000000 لكل خلية. الخلايا الموقوفة لا تستقبل كميات. يدعم JavaScript الصغير التنقل بالأسهم ولصق block من أرقام مفصولة بـtab/newline من Excel، مع رفض اللصق كاملًا إذا احتوى كمية غير صالحة أو خرج عن النطاق/خلية مقيدة. الإدخال والمعاينة والاعتماد يعملان أيضًا دون JavaScript؛ الخادم يعيد كل التحقق ولا يعتمد على parser المتصفح.

المتغير الناقص ينشأ فقط عند وجود كمية موجبة وموافقة صريحة من صاحب catalog.manage. يُشتق من قالب العائلة دون تغيير خواصها، بسعر القالب الأساسي ووحدة بيعه، وSKU داخلي MX-UUID؛ لا اختراع لباركود مصنع أو تعديل سعر متغير موجود. السعر هنا قيمة كتالوج لا تكلفة شراء ولا قيمة قيد مخزني. موظف المخزون يدخل المتغيرات الموجودة فقط؛ لا يرفع صلاحياته بإرسال checkbox أو حقول JSON. إنشاء المتغيرات والكميات والمستند والحركات معاملة واحدة؛ فشل أي خطوة يعيدها كلها.

## المعاينة والتأكيد
POST أول ينتج معاينة بلا تخزين. يعرض الكمية الكلية والجديد والرصيد قبل/بعد، مع إمكانية الرجوع لتعديل المدخلات دون فقد الكميات. payload موقعة لمدة15 دقيقة ومربوطة بالشركة والفاعل والفرع والقالب وإصداره ومفتاح عملية UUID. ليست تفويضًا ثابتًا؛ التأكيد يعيد فحص الصلاحيات والحالة. تغيير سعر/حالة القالب يرفض معاينة قديمة. الرصيد المعروض وقت المعاينة قد يتغير؛ الاعتماد يضيف إلى آخر رصيد ولا يكتب قيمة before مزورة من المتصفح.

كل إضافة operation_key فريد وpayload_digest. إعادة الطلب المطابق ترجع المستند نفسه دون زيادة، واستعمال المفتاح بمحتوى مختلف مرفوض. لا رموز في query strings أو audit؛ المعاينة الموقعة في POST فقط. تتحقق صفحة التأكيد من actor/company قبل خدمة التخزين، وتبقى الضوابط الفعلية داخل الخدمة لأي adapter لاحق.

## نواة الحفظ والتزامن
inventory تطبيق tenant. StockBalance يحفظ الفعلي والمحجوز والإصدار لكل variant/branch، بقيود unique و0≤reserved≤on_hand. StockReceipt وStockMovement غير قابلين للتعديل أو الحذف عبر runtime. الحركة تحمل delta وbefore/after وreserved_after ولقطة SKU/مواصفات/اسم/وحدة، وقيد after=before+delta؛ لا model.save side effects. لا receipts أو balances في public.

تأخذ الخدمة AccessLock داخل معاملة، ثم تقفل أرصدة الصفوف بترتيب variant_id. القفل الواسع الحالي ينسق تغير التفويض والكتالوج والإضافة في الشركة، ويمنع ضياع الزيادة وسباق أول رصيد/أول متغير. تتم المعالجة وbulk_create/bulk_update على دفعات، دون استعلام لكل خلية. اختبار حد الاستعلامات لـ12 خلية جديدة كشف108 استعلامات بسبب إعادة بناء تفويض لكل فعل؛ استبدلت بلقطة تفويض واحدة داخل القفل واجتاز حد100 دون تخفيف السياسة. هذا budget وظيفي وليس قياس حمل إنتاج أو وعد زمن استجابة. تقليل القفل على مستوى SKU مع fencing للتفويض يحتاج تجربة تزامن/حمل R14 قبل تغييره.

المحجوز في هذا الجزء حقل نواة فعلي افتراضيه0، ولا توجد عملية حجز بعد. اختبار تغيير reserved/on_hand مباشرة في قاعدة الاختبار يحاكي قيدًا مستقبليًا لاختبار منع عكس كمية غير متاحة؛ ليس دليل إنجاز الحجز/الصرف في R08-M02. لا جرد مطلق أو تحويل أو فاتورة شراء أو تقييم مالي في إضافة المصفوفة الحالية.

## عكس الإضافة
لا حذف أو تعديل مستند معتمد. صاحب stock.reverse ينشئ StockReceipt مستقلًا يشير للأصل بقيد OneToOne وحركات عكسية. يرفض العكس كله إذا كان أي رصيد سيصبح أقل من المحجوز أو سالبًا، ولا عكس لعكس. نفس operation_key والمحتوى يعيدان المستند نفسه؛ مفتاح مختلف بعد عكس الأصل يرفض دون أثر. تبقى المتغيرات التي أنشئت بالمصفوفة بعد العكس؛ يمكن إيقافها من الكتالوج عند الحاجة بدل حذف هويتها.

## الصلاحيات
أضيف الفعلان stock.receive وstock.reverse إلى سجل السياسة المراجع في الكود. stock.receive لقالب inventory_clerk وbranch_manager والمالك، مع BranchAccess للفرع؛ stock.reverse للمالك فقط في القوالب الحالية. لا محرر أدوار حر أو تغيير Role rows من HTTP. catalog.read مطلوب لشاشات المصفوفة والكتالوج، وstock.read للفرع؛ يجب إسناد catalog_reader صراحة لموظف المخزون وفق ADR 0008. إنشاء المتغيرات الناقصة يحتاج catalog.manage مستقلًا. لا وصول لقارئ كتالوج مجرد إلى الأرصدة، ولا superuser bypass أو كشف رصيد/مستند فرع آخر.

الاختبارات النقية الجديدة تغطي نطاق الفعلين، واختبارات DB/HTTP تغطي سحب الدور بعد المعاينة وعزل actor/company/branch وأحادية المستند. فُصلت R08 إلى خطوات في STATUS والخطة؛ check-rebuild يرفض done لخطوة دون دليل، ويرفض إغلاق أصل له خطوة غير مكتملة.

## التشغيل والحدود
ترحيل migrate-all ثم configure-runtime ضروريان للشركات القائمة؛ provisioning الجديد يمنح الصلاحيات الفنية. لا صلاحيات أو بيانات افتراضية لمستخدم إنتاج. صور المتصفح بيانات صناعية فقط تحت .tools المستبعدة. راجع R08_CHECKLIST وTEST_LOG للأدلة الفعلية.

المراجع التقنية التي راجعت: [Django transactions](https://docs.djangoproject.com/en/5.2/topics/db/transactions/) و[signing](https://docs.djangoproject.com/en/5.2/topics/signing/). القفل والوحدات والحدود قرار للمشروع؛ لا تكفي المعاينة لإثبات مخزون عام أو محاسبة/ضريبة أو تكامل خارجي.
