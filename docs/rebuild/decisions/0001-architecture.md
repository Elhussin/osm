# ADR 0001: بنية الإصدار الجديد

التاريخ: 2026-11-09. الحالة: معتمد كأساس للعمل؛ تفاصيل عزل الشركات قيد الحسم في R02.

## القرار
تطبيق Django واحد بوحدات مستقلة داخليًا، PostgreSQL، Django Templates مع HTMX وAlpine.js عند الحاجة، وتصميم عربي RTL. لا نعتمد Next.js كواجهة التشغيل الافتراضية. API للتكاملات والعملاء الخارجيين والاحتياجات المثبتة فقط. Django Admin للإدارة الفنية.

## السبب
تقليل تكرار النماذج والتحقق وإدارة الحالة بين واجهتين، وإبقاء قواعد ERP في خدمات Python قابلة للاختبار. إعادة البناء مستقلة تشغيليًا عن الإعدادات والبيانات القديمة.

## الحدود
هذا القرار لا يثبت أن تغيير إطار الواجهة وحده يحسن الأداء. نحتاج قياسًا. يمكن إضافة مكوّن عميل تفاعلي عند إثبات الحاجة، خصوصًا لنقطة البيع أو offline، بقرار مستقل.
لا نختار الآن بين عزل schema أو أسلوب آخر دون تحديد عضويات الشركات ومتطلبات العزل. لا تُنشأ migrations الهوية قبل R02.

## قواعد النواة
- خدمات صريحة لحالات المستندات والتحويلات المالية والمخزنية؛ لا آثار ترحيل ضمن save().
- Decimal وقواعد تقريب موثقة؛ فصل حالة المستند عن حالة الدفع وحالة الإرسال الخارجي.
- معاملات وقفل مناسب ومنع تكرار؛ دفتر حركات قابل للتدقيق وعمليات عكس بدل محو التاريخ.
- صلاحية الشركة والفرع والعمل على المستند تتحقق في الخادم.
- تكاملات عبر adapters وoutbox ومهام خلفية، مع تتبع المحاولات وأسرار خارج المصدر.

## التحقق
