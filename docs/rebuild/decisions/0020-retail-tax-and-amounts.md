# ADR 0020 — تصنيف الضريبة والمبالغ ومعاينة السعر النهائي R10-M03

التاريخ2026-11-11. يعتمد ADR0008/0014/0019 وQ10. اختار المستخدم سعر التجزئة النهائي شامل الضريبة عند انطباقها، وخصم البنود ثم خصمًا إضافيًا للإجمالي. هذه نواة حساب ومعاينة محفوظة، دون فاتورة أو XML أو قيد أو تحصيل أو ادعاء امتثال/اتصال.

التصنيف داخل الشركة لكل Variant بإصدارات ثابتة: reviewed أو blocked، وتاريخ بدء ومرجع ومراجع وسبب. الافتراضي غياب التصنيف وليس S أو إعفاء. المراجع يحتاج catalog.read وledger.read وledger.post؛ لا تغيير لقوالب الأدوار أو تجاوز superuser. الاختيار بتاريخ المعاملة بأحدث تاريخ بدء لا يتجاوزها ثم أحدث إصدار؛ الإصدار الجديد لا يسبق آخر تاريخ بدء، ويسمح تصحيح اليوم نفسه مع حفظ السابق. المعاينة السابقة تحتفظ بإصدارها وبياناتها ولا تعاد كتابتها.

نطاق الإصدار SAR وتجزئة عادية منذ2020-07-01: S بالمعدل الأساسي15%، وZ/E/O بمعدل حسابي صفر وسبب رسمي مطابق للفئة. مرجع التصنيف الداخلي إلزامي؛ لا تعيين تلقائي للبصريات أو الخدمات أو التأمين. أسباب مرتبطة بصفة المشتري مثل HEA/EDU/MLTRY لا تطبق كافتراض صنف عام؛ تبقى لسياق معاملة مراجع لاحقًا. حالة البائع unknown تمنع المعاينة. not_registered مسار محلي صريح بلا تحصيل VAT وبلا اختلاق فئة O أو فاتورة ضريبية، وregistered يحتاج تصنيفًا متاحًا لكل بند. صحة التسجيل والمصفوفة التجارية الفعلية Z02/Z03 بوابات تشغيل مستقلة.

الأسعار القديمة وقواعد R07 قبل الضريبة لا تتغير. لكل مدخل أساس صريح: catalog_net يستعمل resolver القديم ولقطته، أو gross سعر نهائي يدوي. لا تحويل بيانات قديمة أو تعديل سعر الكتالوج من المعاينة. الكمية الصحيحة1–1000000 ووحدة SKU ثابتة؛1–40 بندًا. الخصم مبلغ أو نسبة بمنزلتين: يطبق على إجمالي البند الشامل أولًا، ثم يوزع خصم الإجمالي بنسبة الأرصدة الشاملة بعد خصم البنود، بطريقة أكبر البواقي وأولوية ترتيب السطور عند التعادل، دون فقد هللة أو تجاوز البند. لا رسوم أو دفعات مقدمة في الواجهة الحالية.

الحساب Decimal بدقة محلية50 وROUND_HALF_UP. تفصل المبالغ قبل VAT: مبلغ البند الصافي BT131 بعد خصمه، وحصة خصم المستند الصافية BT92، ثم أساس المجموعة BT116 وضريبتها BT117 لكل category/rate. لا تجمع ضرائب الأسطر المقربة بدل ضريبة المجموعة. تحفظ BT106/107/109/110/112/114/115 ومكونات الخصم والأساس الأصلي. فرق الحفاظ على السعر النهائي يظهر مستقلًا كـBT114 ولا يخفى في VAT؛ النطاق الحالي يسمح فرقًا مشتقًا حتى هللة واحدة للمعاينة، ويرفض ما يزيد بدل تغيير الضريبة أو المبلغ المطلوب خفية. هذه حدود دعم معلنة يلزم مراجعتها قبل توسيع الفوترة، وليست اعتمادًا قانونيًا للتقريب. أسباب مختلفة للمجموعة نفسها أو خلط O مع خصم مستند لفئة أخرى يرفضان بدل إسقاط معلومات السبب أو مخالفة BR-O-13.

مدخل الوحدة حتى9999999999.99، والمجاميع حتى9999999999999999.99، دون float/NaN/سالب/دقة إدخال زائدة أو تقريب خفي. السعر الصفري والحسم الكامل صالحان حسابيًا، دون استنتاج معالجة هدايا أو توريد حكمي؛ يلزم سياق تجاري/ضريبي مستقل قبل الإصدار.

TaxQuote ثابت بفرع وتاريخ وإصدار ملف البائع ولقطات التصنيف والسعر والخصم والمجاميع ومعرف UUID ومفتاح طلب وبصمة وسبب وتدقيق. الإنشاء catalog.read وinvoice.read/create للفرع مع وصول حي؛ العميل الاختياري يحتاج customer.read ورابط الفرع الحالي. القراءة تقيد بالفروع وقراءة العميل ورابطه قبل البحث والعد والصفحات وlookup. كل replay يعاد تفويضه؛ المعاملة والقفل المشترك يحفظان لقطة متسقة مع تغييرات الأسعار/الملف/التصنيف. لا أثر مالي أو مخزني في save() ولا شبكة داخل القفل. runtime لا يعدل أو يحذف التصنيفات والمعاينات.

المصادر المقيدة ببصماتها في zatca/SOURCES.json، وربط القواعد المختارة ونطاق تحققها في zatca/CALCULATION_RULES.md. يختبر PostgreSQL الهوية والعزل والتزامن والذرية والمنح والتاريخ، ووحدة حساب بأمثلة رسمية وحالات حدود مستقلة، وHTML/CSRF ومتصفح للهاتف دون JavaScript وسطح المكتب. can_issue_invoice وcan_submit_to_zatca يظلان false في المعاينة؛ SDK وXML والشهادات والبيئة والإقرارات ليست مثبتة بهذه الاختبارات.
