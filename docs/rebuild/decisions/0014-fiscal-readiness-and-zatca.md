# ADR 0014 — التهيئة الضريبية ومسار ZATCA قبل المحاسبة والفواتير

التاريخ:2026-11-10. طلب المستخدم مراعاة متطلبات هيئة الزكاة والضريبة والجمارك أثناء الإعداد. يعتمد ADR 0001/0003/0005/0008؛ لا تغيير لعزل الشركات أو قوالب الأدوار. هذه بداية R09 وليست اعتماد امتثال.

## القرار والنطاق
تقسم R09 إلى M01 للملف الضريبي ومتطلبات الربط، M02 لدليل الحسابات والفترات، M03 لترحيل القيود وعكسها، M04 للواجهات وميزان المراجعة والتحقق. لا تنتقل R10 قبل اكتمال النواة. لم ينفذ دفتر الأستاذ أو محرك ضريبة أو فاتورة أو موصل ZATCA ضمن M01.

تطبيق finance داخل TENANT_APPS فقط. FiscalProfileRevision نسخة محفوظة متسلسلة للكيان القانوني داخل الشركة: الاسم القانوني وحالة تسجيل VAT ورقمه والسجل التجاري والعنوان الوطني الأولي؛ SAR وSA نطاق الإصدار الأول. يسمح بحفظ بيانات أولية ناقصة وتظهر نواقصها صراحة. حالة التسجيل مجهولة افتراضيًا، ولا يفترض تسجيل كل شركة أو خضوع كل صنف لنسبة واحدة. رقم VAT المسجل يفحص بنية15 رقم ASCII فقط في هذه الخطوة؛ لا يثبت صحة التسجيل لدى الهيئة. لا نسخ لأسرار أو شهادات أو OTP في هذا النموذج.

القراءة والكتابة company.manage الحية للمالك ومسؤول الشركة؛ لا توسيع لدور المحاسب/مسؤول الربط ولا اعتماد superuser. خدمة حفظ صريحة داخل atomic وAccessLock، وإصدار متوقع ومفتاح طلب وبصمة تشمل الشركة والفاعل والبيانات. تعاد الصلاحية قبل replay. كل حفظ نسخة جديدة؛ لا تعديل أو حذف السابقة، وruntime بلا UPDATE/DELETE. التدقيق action/target فقط دون عنوان أو رقم ضريبي في payload. قوائم التاريخ20/صفحة داخل الشركة. الفاتورة المستقبلية تحفظ لقطة وإصدار الملف وقت إصدارها؛ تعديل الإعدادات لا يعيد كتابة فواتير سابقة. عنوان الفرع الفعلي وبيانات المشتري يضافان لمسار R10 ولا يفترض أن العنوان القانوني الواحد يكفي لكل الفروع.

قائمة الاستعداد تفصل اكتمال البيانات المحلية عن صحة التسجيل وعن جاهزية المحرك والفاتورة والربط. can_issue_tax_invoice وcan_submit_to_zatca ثابتان false في هذه الخطوة، حتى مع ملف كامل أو إدخال connected=true في POST. لا اختيار إنتاج أو زر إرسال أو endpoint ربط مخفي. تنفذ R13 التسجيل والشهادات والموصل والعامل بعد بوابات R10، وتحتاج أدلة مستقلة لا flags يحددها المستخدم.

## توزيع المتطلبات
| الجزء | ما يجب تأسيسه | بوابة القبول |
|---|---|---|
| R09-M01 | ملف البائع وإصداراته، سجل المصادر والفجوات، حالة استعداد صادقة | عزل وصلاحيات وCSRF وتكرار وتنافس وrollback ومنح PostgreSQL ومتصفح |
| R09-M02–M04 | Decimal وموازنة القيود والفترات وعدم تعديل المرحل والعكس | لا float أو ترحيل مرتين؛ اختبارات تزامن وفشل ومنح ومطابقة |
| R10 | تصنيف ضريبي مؤرخ لكل بند، خصومات وتقريب ودفعات مقدمة وإجماليات ولقطات ومراجع إشعارات | أمثلة رسمية وقواعد XML محددة، وفاتورة ضريبية/مبسطة وإشعارات، ورفض إصدار ناقص |
| R10/R13 | مستند ثابت بهوية UUID وتسلسل وإصدار وحالة خارجية مستقلة؛ تجهيز XML والتحقق والحفظ | لا يحول QR المنتج Code128 إلى QR فاتورة؛ حفظ XML/نتيجة التحقق ومراجع الإشعارات |
| R13 | EGS لكل وحدة مناسبة، الشهادات ومراجع أسرارها، hash chain والتوقيع وQR، clearance/reporting/outbox | اختبار SDK الرسمي ثم بيئة الهيئة؛ إعادة محاولة الشبكة للمستند نفسه لا تعيد ترقيمه، والتصحيح بعد رفضه مستند جديد يحفظ المرفوض؛ لا أقفال أثناء الشبكة |
| R14/R15 | حفظ وأرشفة ونسخ واستعادة ومطابقة وتقارير ضريبية | سياسة حفظ مقررة من اللوائح الحالية، تجربة استعادة وقبول ومراجعة نطاق الشركة |

الخدمة/التصنيع/العدسات أو الدفع بالتأمين لا تحدد وحدها المعاملة الضريبية. تصنيف السلع والخدمات والتأمين وصفة المشتري والخصومات والإشعارات يحتاج مصفوفة محاسب ومراجع رسمية قبل اعتماد R10. لا حساب آلي للزكاة أو تقديم إقرار VAT ضمن ربط الفوترة الإلكترونية، ولا ادعاء أن نجاح الفوترة يثبت كل التزامات المنشأة.

## المرجع الرسمي والإثبات
رقم إصدار الملف ليس عدّاد الفواتير أو تسلسل وحدة EGS. يربط R13 هوية الشهادة بالشركة والبيئة ووحدة الإصدار، ويعيد فحص توافقها عند تغيير بيانات الهوية؛ لا يستبدل بيانات فاتورة محفوظة أو يعيد استخدام شهادة تلقائيًا مع هوية أخرى.

راجع docs/rebuild/zatca/REVIEW.md للمصادر والإصدارات وحالة كل مستند والفجوات. توثيق مايو2023 الظاهر على الصفحات الرسمية راجع في2026-11-10؛ تاريخ تحديث الصفحة ليس إصدارًا جديدًا للمواصفة. لا ادعاء اختبار SDK أو sandbox أو simulation أو إنتاج في M01. لا ترسل بيانات أو تستخدم بوابات حقيقية من هذه الخطوة.
