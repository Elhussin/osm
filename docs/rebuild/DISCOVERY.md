## قواعد مستخرجة مقابل تغييرات مقترحة
- المرجعي: subtotal هو مجموع total_price، وtax_amount = subtotal × tax_rate، وtotal = subtotal + tax - discount في sales/services/base_document_service.py. هذا وصف التنفيذ، وليس اعتمادًا لمعالجة ضريبية صحيحة. موضع الخصم والضريبة والتقريب سيُحسم في R09/R10.
- المرجعي: OrderItem يربط المتغير بالوصفة، والطلب له حالات pending/confirmed/ready/delivered/cancelled. البديل يحفظ لقطة المواصفات والسعر وقت العملية ويختبر انتقالات الحالة بدل السماح بتعديلها كحقول CRUD.
- المرجعي: available_quantity = quantity_in_stock - reserved_quantity. البديل يمنع تجاوز الحجز والصرف بالتزامن ويُعرّف بوضوح متى يستهلك الحجز.
- المرجعي: المتغيرات تستخدم خصائص ثابتة وAttributeValue ووراثة متعددة الجداول. ننقل المعنى وليس شكل الجداول آليًا.
- المرجعي: اختيار أول قاعدة سعر مطابقة دون أولوية عمل معلنة. البديل يحتاج ترتيبًا صريحًا ونتيجة ثابتة عند التداخل.
- المرجعي: توليد رقم الفرع والوثيقة يعتمد على العد أو آخر سجل؛ البديل يحتاج ترقيمًا آمنًا عند التزامن.
- الواجهة تحتوي تحقق وصفات إضافيًا لا يكفي الاعتماد عليه في الخادم. توحيد التحقق يشمل حفظ القيم الصفرية وتمييزها عن الحقول الفارغة.

## الواجهات ومسارات العمل
المسارات الموجودة في osmFront/src/app تشمل product وprescription وdashboard/[entity]، والمصادقة والصفحات ودفع الاشتراك. لا يوجد مسار POS مستقل مثبت بالحصر. راجع views وurls لكل وحدة عند إعادة تنفيذها؛ وجود route لا يثبت قابلية تشغيله.
لا نعيد بناء universal form generator أو عميل OpenAPI مولد لكل شاشة. تُستخرج منه أسماء الحقول والعلاقات فقط؛ واجهة العمليات الجديدة تبنى حول المهمة.

## حدود الحصر الآلي
`legacy-inventory.csv` يسجل كل ملف legacy متتبع موجود وقت توليده وتصنيف مصيره ومرحلة مراجعته. التصنيف حسب المسار بوابة مراجعة، وليس شهادة فحص كل سطر. لا يتضمن محتوى ملفات البيئة أو بيانات العملاء. ملفات static والوسائط والبيانات والترحيل لا تُنسخ إلى التطبيق الجديد.
السيناريوهات في SCENARIOS.json عقد قبول مستقبلي، وليست اختبارات وظائف نجحت بالفعل. يتحقق فحص R01 من تغطيتها ومصادرها فقط.

## تحديث المستخدم بعد الحصر
حُسم Q01 نطاقًا: وصيل API لجلب بيانات العميل والأهلية والموافقات والمطالبات، مع إذن ببناء الخطوات قبل توفير الوثائق والمفاتيح. لم يقدم المستخدم موقع كود إضافي؛ لم يعد العثور عليه شرط بدء تصميم R12. يبقى غياب التنفيذ المرجعي نتيجة الحصر، وتضاف قواعد مزود موثقة لاحقًا وفق Q12.
حُسم Q02: متصل بالإنترنت أولًا. Q03/Q04 مؤجلان لاختيار الأجهزة لاحقًا. R02 يمكنه البدء، ويمكن تصميم POS العام دون انتظار أجهزة؛ قبول وظائف الطباعة والأجهزة يحتاج تحديدها. لا نحذف أي مرجع تأمين قد يظهر لاحقًا قبل مراجعته.
