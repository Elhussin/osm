# معايير القبول والاختبارات

## تعريف الإنجاز لكل مهمة
1. تحقق المخرجات المحددة في PLAN.md مع توثيق قراراتها.
2. إضافة اختبارات سلوك فعلية للنجاح والفشل والصلاحيات، وتشغيلها.
3. توثيق الأمر والبيئة والنتيجة والقيود في TEST_LOG.md وربط معرف الدليل بالمهمة.
4. تحديث STATUS.json والخطة وسجل التغيير. لا أدلة نجاح لشيء لم ينفذ.
5. تحديث CLEANUP.md عند الحذف وفحص المراجع المتبقية.

## بوابات الاختبار
| النوع | متى | ما الذي يثبت |
|---|---|---|
| فحص الخطة | كل تغيير | تبعيات المهام وأدلة الإنجاز والملفات المرجعية |
| وحدة | قواعد تحقق وحساب وحالات | المخرجات المتوقعة وحالات الحدود والرفض |
| PostgreSQL | أي نموذج أو خدمة تخزن بيانات | القيود والمعاملات والعزل؛ قاعدة اختبار مستقلة |
| تزامن | حجز وصرف ودفع وترقيم وترحيل | طلبان متزامنان لا يكرران الأثر ولا يتجاوزان الرصيد |
| متصفح | كل مسار مستخدم مكتمل | الاستخدام الفعلي، RTL، الصلاحيات، الأخطاء، لوحة المفاتيح |
| عقد تكامل | كل موصل | الطلب والاستجابة والتوقيع إن وجد والمهلة وإعادة المحاولة |
| sandbox | قبل اعتماد التكامل | نتيجة موثقة من بيئة المزود وإصدار مواصفاته |
| تشغيل | قبل الإصدار | الاستعادة والنقل والرجوع والحمل ومطابقة الأرصدة |

## سيناريوهات إلزامية للوحدات الحساسة
- العزل: شركتان وحسابان مستقلان حتى لو تشابه اسم الدخول، وفروع بصلاحيات مختلفة، وصول مباشر إلى معرف لا يملكه، صلاحية ملغاة. لا حساب متعدد الشركات حسب قرار المستخدم. حالات السياسة P01–P40 لا تعوض إثباتات PostgreSQL/HTTP في I01–I20 (ACCESS_VERIFICATION.md).
- المخزون: طلب آخر قطعة بالتزامن، تحرير حجز غير موجود، الإلغاء مرتين، التحويل الجزئي، before/after صحيحان.
- المال: حفظ دفعة موجودة، طلب دفع مكرر، تجاوز المبلغ، فشل منتصف المعاملة، عكس دفعة، منع ترحيل غير متوازن.
- التأمين: انتهاء أهلية، موافقة جزئية، رفض، مهلة بعد إرسال ناجح، استجابة مكررة، تسوية جزئية.

## دليل الاختبار
لكل نتيجة: معرف مثل T000، معرّف المهمة، تاريخ، أمر قابل للتكرار، بيئة، passed/failed/blocked، ملخص النتيجة والقيود. يقرأ فحص الخطة معرفات النجاح بصيغة `## T000 | passed`؛ النص التفصيلي مسؤولية منفذ المهمة ومراجعتها، ولا يعد الفحص بديلًا عن تشغيل الاختبارات.

## امتداد R06 — الصورة الاختيارية
حفظ القياسات دون صورة مسار ناجح مستقل. الصورة المرفقة JPEG/PNG مقيدة الحجم والأبعاد ويعاد ترميزها وتزال metadata، مع رفض atomic للملف غير الصالح. القراءة والتنزيل يحتاجان الشركة والفرع وصلاحية الوصفة الحية؛ مشاركة العميل لا تكشف فحوص الفروع الأخرى. تصحيح الصورة أو إزالتها من إصدار جديد يبقي الأصل وتاريخه. صورة وحدها تظهر كتسجيل توثيقي دون قياسات جاهزة للبيع؛ ربط إصدار الوصفة واللقطة بطلب يُختبر في R10. تفاصيل الحدود والنتائج في ADR 0007 وR06_CHECKLIST وT015/T016.

## امتداد R07 — المتغيرات والأسعار
مخططات أنواع واضحة، ووحدانية المواصفات المطبعة وSKU/باركود داخل الشركة. وحدة البيع ثابتة ولا تحويل ضمني، والسعر الصفري مختلف عن غياب القاعدة. أولوية العميل ثم الفرع ثم العام وحد الكمية الأعلى داخل النطاق، مع قناة وفترة شاملة؛ رفض تداخل النطاق نفسه والتعادل، واختبار طلبين متزامنين. لا بيانات عملاء خاصة من دور قارئ الكتالوج، ولا معاينة دون صلاحية الفرع. اللقطة لا تتغير بتغيير الكتالوج ولا تمنح اعتماد بيع؛ إعادة التسعير والحفظ مع الطلب R10. الدليل T017/T018 والحدود ADR 0008.

## امتداد R08-M01 — مصفوفة العدسات
عرض SPH/CYL حسب عائلة الصنف ووحدته والفرع، وإضافة كميات بمعاينة دون حفظ ثم تأكيد يعيد التفويض، ومفتاح طلب يمنع التكرار. لا إنشاء ناقص دون catalog.manage أو لخلايا صفرية/فارغة، ولا حفظ جزئي عند خطأ. عكس مستقل يمنع السالب أو استهلاك المحجوز، وتبقى المستندات واللقطات. لصق وهاتف ولوحة مفاتيح وبدون JavaScript واختبارات تزامن وعزل وقيود DB. أدلة T020/T022 تغلق M01 فقط، ولا تغلق الحجز/الصرف والتحويل/الجرد والدفعات/التسلسلات في R08-M02–M04. يفحص سجل الخطة أدلة الخطوات ويمنع parent done مع خطوة معلقة.
