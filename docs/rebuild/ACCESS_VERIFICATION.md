# R02 — التهديدات وخطة إثبات العزل

التاريخ: 2026-11-09. السياسة الحالية في rebuild/access/policy.py، وحالات P01–P40 في access-matrix.json؛ الأربعة اختبارات الإضافية تتحقق من السجل وحد الشركة لكل فعل واستقلال التقييم بين الطلبات. هذه اختبارات Python فقط.

## حدود الثقة
المتصفح غير موثوق، بما فيه host غير مسجل وtenant/schema وbranch/user/provider identifiers. يتم اعتماد المضيف من الدليل قبل الجلسة، وحل المستخدم من المخطط الصحيح، وتحميل التعيينات والفروع الحالية في الخادم. لا تمرر dataclasses من JSON العميل إلى permits مباشرة.

مخرجات permits ليست token أو موافقة أبدية. يُعاد التحقق عند كل عملية، وفي العامل قبل الأثر. queryset محمل قبل تغيير tenant_context لا يعاد استخدامه. UUID عشوائي يقلل التخمين لكنه ليس تفويضًا. الأخطاء العامة لا تكشف إن كان المستند أو البريد موجودًا في شركة أخرى.

## مصفوفة التهديدات والاختبارات المتبقية
الحالة الأصلية لجميع I01–I20 كانت planned في R02؛ الأدلة الجزئية الجديدة أدناه لا تغلق البنود الكاملة تلقائيًا. IDs ثوابت تُحفظ عند تحويلها لاختبارات Django/PostgreSQL. لا تغلق R04 قبل نجاح بنودها الخاصة بالهوية والعزل؛ البنود المرتبطة بوحدات لاحقة تُغلق في مراحلها المحددة في الجدول. لا تختزل أي بند في اختبار سياسة P.

تحديث R03: اجتاز الأساس محليًا I01، وجزء المصادقة الداخلية من I02، واستقلال مخزن الجلسات من I03، ورفض النطاق غير المسجل من I04، وschema_context بعد استثناء من I06، ومنع runtime من CREATE schema/table وتعديل الدليل من I11، ورفض الشركة المعلقة من I12. هذه أدلة جزئية محددة في foundation_tests/test_schemas.py وverify_runtime_role؛ لا تعني اكتمال تسجيل الدخول HTTP أو الدعوات أو الفروع أو العامل أو بقية أجزاء البنود. الجدول أدناه هو متطلبات الإغلاق النهائية في مراحلها.

تحديث R04: تنفذ access_tests اختبارات HTTP للدخول ورفض cookie شركة أخرى وCSRF وخواص cookie الإنتاج، ونطاق الفروع قبل count، وسحب الدور أثناء session، وتزامن طلبات شركتين، ونقل ملكية متزامن، واستعادة الروابط المقيدة بالشركة والغرض والصلاحية، وقيود audit بدور PostgreSQL محدود. النطاق الحالي I02–I10 وI12 وI19 وI20 في بيانات الهوية والفروع، مع إعداد محلي لـI14/I17. يبقى I13 للتنزيل/cache والتصدير عند بناء تلك الوحدات، وI14/I17 للإرسال الفعلي ومصادقة queue في R13، وI15/I16/I18 لمراحل الأعمال. لا اختبار متصفح بصري أو قناة بريد فعلية في هذا الدليل؛ مرجع الحدود ADR 0005.

## شروط ربط السياسة في R04
- يبنى Principal/CompanyContext من بيانات موثوقة حية؛ User ضمن schema واحد، لا memberships متعددة الشركات.
- ResourceScope.branch_ids مجموعة كل الفروع اللازمة للعملية. قراءة العميل المشترك تستخدم فرع العلاقة المصرح له، ولا تحول وجود رابط واحد إلى قراءة جميع وصفاته.
- توجد خدمات منفصلة للتفويض وتصفية querysets والمنح ونقل الملكية. ليست permits بديلًا عن هذه الخدمات أو حماية middleware أو قاعدة البيانات.
- ROLES الحالية قوالب ثابتة مقصودة في R02. إن أضيف تخصيص أدوار من قاعدة البيانات، يجب تحميل permissions من سجل الأكواد المسموح وبنفس scope والتحقق من المنح المتعدي، واختبار resolver قبل تفعيل محرر الأدوار. لا تسمح قيمة role مجهولة بوصول احتياطي.
- أوامر الإدارة تستخدم actor موثقًا أو هوية provisioning مع سجل مستقل؛ امتلاك shell ليس ترخيصًا لواجهة عامة تتجاوز الشركة.

## التشغيل الآن
من جذر المستودع وباستخدام Python صالح:

```powershell
python -m unittest discover -s rebuild/tests -v
```

تم التشغيل بمفسر Python المرفق بتبعيات التطبيق. لا حاجة Django أو PDM لاختبار السياسة المجردة. نجاحه لا يثبت I01–I20 ولا يغلق R03/R04.

## تحقق مصفوفة المخزون R08-M01
inventory_tests وbrowser_tests/test_inventory_browser تغطي I07/I08/I13 على أرصدة ومستندات المصفوفة: تصفية قبل aggregate/lookup، فرع وشركة وفاعل آخر، سحب الدور بعد المعاينة، وتوقيع ومدة وإعادة تفويض. اختبارات receive/reverse والتكرار/rollback/التزامن وقيود الحركة والمنح لا تغلق I16 للتحويل أو الحجز/الصرف أو الجرد؛ تظل تلك أدلة مستقبلية R08-M02/M03. لا proof إنتاج لمجرد حقل reserved أو لقطة تفويض داخل معاملة.

## تحقق الحجز R08-M02
أضيف test_reservations لتنافس المخزون والتكرار وrollback وسحب الدور حتى replay، وقيود المعادلة ومنع تعديل الهوية والأحداث تحت دور PostgreSQL محدود. اختبارات HTTP ترفض فرعًا/شركة أخرى وكمية أكبر وإصدارًا قديمًا وCSRF، وخيارات الأصناف تصفى قبل حد100 والبحث. متصفح Chromium يختبر الصرف والتحرير بالأوامر المسماة، والهاتف دون JavaScript والإلغاء والعكس وانعكاس المتاح في المصفوفة. النتيجة النهائية والدليل العددي في TEST_LOG؛ يظل I16 للتحويل وR08-M03 غير مغلق بهذه الاختبارات.

## تحقق التحويل والجرد R08-M03
test_operations يضيف إثبات I16 على النقل الداخلي الفوري: إذن الفرعين وstock.read معًا، وحركتان متوازنتان ورصيدان داخل المعاملة، ومنع استهلاك المحجوز، وrollback والتكرار والعكس. lookup والقائمة تصفيان قبل الحد والعداد، ورفض الوجهة المزورة وسحب الدور على replay واختبارات schema أخرى. اختبار ترحيل فعلي بين inventory.0002 و0003 يثبت backfill فرع حركات الإضافة والصرف دون تغيير التاريخ، ودور runtime ينفذ نقلًا وعكسًا وجردًا دون UPDATE/DELETE على مستنداته أو حركاته. الجرد يثبت snapshot قديمة وكمية أقل من المحجوز وقراءة مطابقة ومنع العكس بعد حركة لاحقة. النتيجة النهائية في TEST_LOG؛ لا إثبات دفعات/تسلسلات أو شحن/استلام مؤجل بهذا النطاق.
