# التأمين عبر وصيل — متطلبات المستخدم وحدود التنفيذ

التاريخ: 2026-11-09. المصدر: إجابة المستخدم في هذه المحادثة. هذه مواصفات داخلية مقترحة، وليست توثيقًا لواجهة وصيل أو أسماء endpoints أو حالات استجابة معتمدة من المزود.

تحديث بعد إضافة الحزمة: استلمت وثائق Excel وPostman وأمثلة JSON؛ [مراجعة العقد والفجوات](waseel/REVIEW.md) و[الحصر التقني المنقح](waseel/contract-inventory.json) هما مرجع التفاصيل. وردت قيم اعتماد في الأمثلة لكنها لم تستخدم ولم تتحقق صلاحيتها. ورود الوثائق لا يعني جاهزية الاتصال الفعلي.

## النطاق المطلوب
الربط عبر API منصة وصيل لتوفير أربع عمليات:
1. جلب بيانات العميل.
2. التحقق من الأهلية (Eligibility).
3. إنشاء طلب موافقة ومتابعة نتيجته عند توفر آلية ذلك في API.
4. رفع المطالبات وتتبع نتيجة الإرسال وفق ما توثقه المنصة.

يمكن بناء خطوات العمل والنماذج والخدمات الداخلية بناء على الوثائق المستلمة مع حصر تعارضاتها. ثبت وجود طلبات بحث وتواصل وإلغاء للموافقات في Postman؛ لا نفترض دعم تسويات أو webhook أو ضمان منع تكرار. واجهة JSON المقدمة تذكر NPHIES وتوفر حقولًا مخصصة، وليست إذنًا بإرسال FHIR Bundle مباشرة. لم يثبت مسار مستقل لجلب العميل ولا endpoint لرفع المطالبات في هذه الحزمة.

## الفصل بين العمل الداخلي والإرسال
- لكل طلب شركة وفرع وعميل ومعرف داخلي وسجل أحداث ومستخدم منفذ؛ لا وصول عبر الشركات.
- جلب بيانات العميل ينشئ نتيجة مراجعة: لا يستبدل البيانات المحلية تلقائيًا ولا يدمج هويتين متشابهتين دون تحقق وموافقة الموظف المخول.
- سجل الأهلية منفصل عن الموافقة. نجاح الأهلية لا يعني اعتماد التغطية أو السماح بترحيل مطالبة.
- طلب الموافقة يحمل لقطة الوصفة والخدمات والأسعار عند الإرسال. تعديل الطلب بعد ذلك يحتاج إصدارًا جديدًا أو إجراءً يدعمه المزود صراحة.
- المطالبة تُجهز داخليًا من التنفيذ الفعلي والمراجع اللازمة وفق عقد المزود؛ لا نعتمد موافقة تأمينية مختلقة أو نرسل مطالبة تلقائيًا من حفظ النموذج.
- مسؤولية العميل والممول وقيمة الموافقة وحدودها سيحكمها الرد الموثق وقواعد التسعير المعتمدة، وليس افتراض تغطية كاملة.

## حالات داخلية مقترحة
حالة الإعداد منفصلة عن النقل والنتيجة التجارية. هذه أسماء داخلية قابلة للتعديل قبل تنفيذ R12:
- الإعداد: draft / ready / cancelled، مع تدقيق صلاحية الانتقال.
- النقل: not_sent / queued / sending / acknowledged / failed / unknown_outcome / simulated.
- القرار التجاري: pending / approved / partially_approved / rejected / expired، فقط حين يوجد رد مثبت يدعم المعنى. لا تفرض هذه الحالات على جميع أنواع العمليات.

عند غياب الوثائق أو الإعدادات، يمنع موصل الإنتاج الإرسال برسالة واضحة؛ يمكن استخدام موصل محاكاة في الاختبار مع علامة simulated ظاهرة. لا تحول المحاكاة طلبًا إلى موافقة حقيقية ولا تستخدمها لترحيل مطالبة فعلية.

## الواجهة الداخلية للموصل
عمليات تطبيقية مقترحة: fetch_customer، check_eligibility، submit_authorization، submit_claim. هذه ليست أسماء endpoints. ينتج الموصل نتيجة موحدة تتضمن العملية والمعرف المحلي والمرجع الخارجي إن وجد وحالة النقل والقرار إن أمكن وتاريخ الاستجابة. تحفظ البيانات الحساسة بالحد اللازم، وتحجب المفاتيح والبيانات الشخصية عن السجلات العامة.

الإرسال يتم بمهام خلفية وoutbox دون إبقاء قفل قاعدة البيانات أثناء الاتصال. نطاق منع التكرار يشمل الشركة والعملية والطلب وإصداره. المهلة بعد إرسال الطلب تنتج unknown_outcome؛ لا تعاد عملية ذات أثر خارجي تلقائيًا حتى تتضح آلية الاستعلام أو منع التكرار لدى المزود. هذا مطلوب داخلي لحماية المعاملة، وليس ادعاء دعم وصيل لهذه الآليات.

## خطة الاختبارات
### R12 — عقد محلي ومحاكاة دون اتصال
اختبارات سير العمل والصلاحيات، منع تخطي الأهلية/الموافقة المطلوبة حسب القواعد المعتمدة، موافقة جزئية ورفض وانتهاء، لقطة البيانات، مراجعة بيانات العميل، منع التكرار الداخلي، فشل المهمة، ظهور علامة المحاكاة، ومنع إرسال الإنتاج عند غياب الإعدادات. المدخلات صناعية والردود مصطنعة وموسومة.

### R13 — بعد توفير التكامل
عقد طلب/استجابة مستخرج من الوثائق، توثيق المصادقة وانتهاء بياناتها وأكواد الأخطاء والحدود، اختبار sandbox لكل عملية، حالات المهلة والرد المكرر، واستعادة حالة طلب غير معروف المصير بالطريقة التي يتيحها المزود. لا يُعلن اتصال ناجح أو توافق قبل وجود دليل من بيئة المزود.

## ما نحتاجه لاحقًا — Q12
استلمت وثائق v2 وأمثلة المصادقة والطلبات؛ المتبقي تأكيد الإصدار وتفعيل sandbox ورد المصادقة وصلاحية الرمز وربط الشركة/الفرع وعقد المطالبات والجلب المستقل وحسم تعارضات الوصفة والأرقام. التفاصيل W01–W07 في waseel/REVIEW.md. لا تطلب المفاتيح في المحادثة ولا تحفظها في المستودع؛ قيم الأمثلة ليست دليل تفعيل الحساب.

## حالة التنفيذ
تم توثيق النطاق ومراجعة الحزمة واختبار استخراجها المنقح؛ لم ينفذ موصل أو نموذج أو اختبار وظيفي للتأمين بعد. يمكن بناء R12، واعتماد الربط الفعلي في R13 ينتظر حسم الفجوات واختبار المزود.
