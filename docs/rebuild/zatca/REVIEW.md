# مراجعة ZATCA — الاستعداد والحدود

تاريخ المراجعة2026-11-10. الاسم الحالي: هيئة الزكاة والضريبة والجمارك. طلب المستخدم ربطها ومتطلباتها أثناء الإعداد؛ هذا السجل يميز التنفيذ المحلي عن الإثبات الرسمي. لا بيانات منشأة حقيقية أو بيانات اعتماد مستخدمة.

## المصادر الرسمية التي راجعت
| المعرف | المصدر | الإصدار/ما تمت مراجعته |
|---|---|---|
| ZS01 | [مواصفات الفاتورة](https://zatca.gov.sa/en/E-Invoicing/SystemsDevelopers/Pages/E-Invoice-specifications.aspx) | الصفحة تعرض Data Dictionary وXML Standard بتاريخ19 مايو2023؛ يجب تثبيت نسخة وقواعد كل منهما عند R10 |
| ZS02 | [الدليل التفصيلي الرسمي](https://www.zatca.gov.sa/en/e-invoicing/introduction/guidelines/documents/e-invoicing_detailed__guideline.pdf) | Version2 مايو2023،66 صفحة؛ أنواع المستندات ومسار الاعتماد والإبلاغ والممنوعات والحفظ والتكامل |
| ZS03 | [مواصفات الأمان الرسمية](https://zatca.gov.sa/ar/E-Invoicing/SystemsDevelopers/Documents/20230519_ZATCA_Electronic_Invoice_Security_Features_Implementation_Standards_vF.pdf) | Version1.2،27 صفحة؛ إدارة شهادات الختم وسلسلة hash ومكونات QR |
| ZS04 | [ضوابط التنفيذ](https://www.zatca.gov.sa/en/RulesRegulations/Taxes/Pages/ConReqTech.aspx) | صفحة نشر تحديث19 مايو2023؛ لا تعد هذه المراجعة القانونية الشاملة للائحة VAT |
| ZS05 | [مراحل التطبيق](https://zatca.gov.sa/en/E-Invoicing/Introduction/Pages/Roll-out-phases.aspx) | الفصل بين توليد/حفظ الفواتير والربط المرحلي؛ استهداف المنشأة يثبت بإشعارها، لا بحجم متجر نفترضه |

ZS02: الفصل6.4 يفرق بين اعتماد الفاتورة الضريبية قبل مشاركتها والإبلاغ عن المبسطة خلال24 ساعة من توليدها؛ لذلك لا يكفي إرسال خلفي واحد لكل الأنواع. الفصل4.3 يغطي الإشعارات، والفصل6.5 الممنوعات، والفصل7.3 الحفظ. يتعين تحويلها لقواعد واختبارات قبل الإصدار. ZS03 الفصل3 يحدد previous invoice hash، والفصل4 محتويات QR والفصل2 الشهادات والختم. باركود SKU الحالي للمخزون لا يؤدي أيًا من وظائف QR الفاتورة.

تعذر جلب PDF الخاص بـXML Standard عبر أداة الويب مرتين (timeout)، رغم قراءة صفحة ZS01 الرسمية. لم يقرأ ملف Data Dictionary نفسه أو عقد API أو أدوات SDK بعد؛ لا ندعي استكمال مراجعتها أو نختلق أمثلة. لم تنزل مكتبة خارجية لتقوم مقام مواصفات الهيئة. الإصدار الظاهر على صفحة موقع ليس دليلًا على عدم وجود تحديثات؛ يعاد التحقق قبل بوابة التكامل.

## فجوات تمنع ادعاء الجاهزية
| المعرف | المتبقي | البوابة |
|---|---|---|
| Z01 | تنزيل وتثبيت XML Standard وData Dictionary وربط IDs القواعد بالحقول والأمثلة الرسمية والتقريب | R10 قبل إصدار فواتير |
| Z02 | مصفوفة ضريبة معتمدة بحسب السلعة/الخدمة وصفة المشتري والتأمين، الخصم/المقدمات/المرتجعات ومراجع الإشعارات؛ لا افتراض إعفاء البصريات أو نسبة افتراضية لكل الأصناف | R09/R10 مع المحاسب |
| Z03 | بيانات التسجيل والعناوين والفروع الفعلية ووحدات EGS المستهدفة وموجة المنشأة | إعداد R10/R13 قبل التشغيل الفعلي |
| Z04 | API وSDK الرسميان بإصداراتهما، عينات تحقق محلية رسمية ونتائج محفوظة | R10/R13؛ لا تكفي وحدة Python أو mock |
| Z05 | مفاتيح/CSR وشهادات وتسجيل وتجديد/إلغاء وفصل بيئات وتجارب clearance/reporting وأخطاء المهلة/التكرار | R13 قبل تفعيل الإنتاج |
| Z06 | سياسة حفظ من اللوائح الحالية، تخزين XML والتوقيع والاستجابات، نسخة واستعادة ومطابقة مع المحاسبة وتقارير الضريبة | R14/R15 قبل الإصدار |

## حالة المنتج
M01 يبني ملف بائع أوليًا بإصدارات وقائمة نواقص وحالة غير متصل فقط. لم ينفذ محرك VAT أو فاتورة أو XML أو توقيع أو QR فاتورة أو SDK أو اتصال بالهيئة. لا يوجد endpoint إرسال إنتاج. اكتمال الحقول المحلية لا يثبت التسجيل الصحيح أو المطابقة أو الربط. لا نشر لبادج «معتمد من الهيئة»، ولا ربط بإقرار أو حساب زكاة تلقائي من هذا العمل. مصدر أدلة الاختبارات المنفذة TEST_LOG، وإغلاق كل بوابة مستقل في STATUS.
