# تحقق R06 — العملاء والفحوص والوصفات

- إنشاء عميل والبحث بالاسم والهاتف والوثيقة وتعديل مع كشف النسخة القديمة؛ حقول اختيارية وتطبيع الأرقام العربية وتاريخ ميلاد صالح.
- CustomerBranchAccess صريح؛ حساب الفرع لا يحصل على عدد أو ملف أو وصفة أو صورة لفرع آخر. مشاركة بيانات العميل لا تشارك الفحوص، وتعديل المشترك يحتاج جميع الفروع.
- حفظ SPH/CYL/AXIS/ADD/PD للعينين بتمييز الصفر عن الفراغ، وربط الفحص بتاريخ ومصدر وفاحص وملاحظات.
- رفض محور خارج النطاق وCYL غير صفرية دون محور وقيم خارج الحدود/خطوة0.25، ورفض سجل خالٍ دون قياس أو صورة. قيود DB وrollback بلا مستند جزئي.
- صورة اختيارية JPEG/PNG: مع وبدون صورة، وصورة وحدها موضحة كتوثيق، ورفض corrupt/SVG/زيادة الحجم/الأبعاد. إعادة ترميز وإزالة metadata والذيل HTML.
- صورة خاصة لكل إصدار؛ طلب anonymous/شركة أخرى/فرع آخر/كاشير أو دور مسحوب/فرع معطل مرفوض. headers للخصوصية وعدم التخمين، ولا مسار media عام.
- تصحيح بإصدار وسبب وexpected_version؛ قيم/صورة/تعريف العميل واللقطة القديمة محفوظة. إبقاء/استبدال/إزالة الصورة من الإصدار الجديد فقط، وسباق تصحيح واحد مقبول.
- runtime يمنع UPDATE/DELETE على revision/image. سياسة محو البيانات/الاحتفاظ ونمو التخزين ضمن قرارات التشغيل لاحقًا؛ لا حذف تاريخ من الواجهة.
- Chromium: عميل وفحص وصورة وعرض وتصحيح وتاريخ وبحث HTMX، هاتف390/768/1440 وحفظ دون صورة ودون JavaScript، ومنع موظف المبيعات من الملف الطبي.
- إعادة مجموعة R03–R05 والسياسة وفحوص الخطة والحصر؛ لا تعتبر القائمة دليل تشغيل. النتائج في TEST_LOG والحالة في STATUS.

التالي R07: المنتجات ومتغيرات العدسات والإطارات والتسعير، ومراجعة حقول الملاءمة القديمة. تكامل الطلب مع لقطة إصدار الوصفة في R10؛ لم ينشأ طلب أو أثر مالي ضمن R06.
