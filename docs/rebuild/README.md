## قواعد التحديث
لكل جزء معرّف ثابت، وتبعيات، ومخرجات، واختبار قبول. الحالات: pending / in_progress / blocked / done.
لا يُغلق جزء قبل نجاح الاختبارات المرتبطة به. يسجل الفشل أو تعذر التشغيل كما حدث، ولا يستبدل الاختبار بوعد بتنفيذه لاحقًا.
تُحدّث الحالة والخطة وسجل الاختبارات والتغيير عند نهاية كل مهمة. تُضاف القرارات الجديدة كملفات مرقمة، مع سبب القرار وآثاره وطريقة التحقق منه.

## حدود الاستقلال
العمل يتم داخل هذه النسخة؛ لا يُعدّل المشروع الأصلي أو قواعد بياناته. الاستقلال التشغيلي سيتحقق بإعدادات واسم قاعدة ومستخدم وأسرار ووحدات تخزين خاصة في R03. الاستقلال عن المستودع البعيد لم يُنفذ: remote الموروث ما زال موجودًا، ولا يسمح سير العمل بالدفع إليه تلقائيًا.
تُستخدم بيانات صناعية للاختبارات. نقل بيانات حقيقية مرحلة منفصلة تتطلب خريطة تحويل ومطابقة وتجربة رجوع.

## ما يحتاج إثباتًا
- مكان كود التأمين المتقدم: لم يظهر في الملفات المفحوصة؛ لا نعتبره مفقودًا نهائيًا ولا نعيد اختراع قواعده قبل البحث عنه.
- الحاجة للعمل دون اتصال وأجهزة الكاشير والطباعة: تحسم في R01 قبل تثبيت تصميم نقطة البيع.
- لا يوجد قياس أداء عملي للنسخة القديمة حتى الآن.
